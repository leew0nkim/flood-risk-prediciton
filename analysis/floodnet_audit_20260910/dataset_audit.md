# FloodNet CSV dataset audit

분석 대상: 사용자가 제공한 export.csv. 공개 API의 현재 데이터로 교체하지 않고 첨부 파일 전체를 집계했다. 원본은 수정하지 않았다.

**판단**

30분 입력을 유지하여 첫 모델을 개발할 수 있는 규모다. 45분 이상 관측된 이벤트는 2,385건(74.91%)이다. 단, 실제 사용 가능한 연속 구간은 측정 공백에 따라 줄어든다. 원 측정 간격이 180초를 초과할 때 구간을 나누는 시험 기준에서는 30분 입력 + 15분 예측 후보가 1,807개 이벤트, 223,355개 겹치는 구간이다. 20분 입력은 1,990개 이벤트, 246,897개 구간이다.

20분 입력은 이벤트 183건(+10.13%), 후보 구간 23,542개(+10.54%), 상승 후보 구간 8,624개(+34.95%)를 더 확보한다. 30분을 기본안으로 유지하되 20분을 같은 평가 조건에서 비교하는 것이 적절하다. 이는 모델 성능이나 최종 학습 데이터 수를 확정한 결론은 아니다.

**30분 입력과 20분 입력 비교**

아래 수치는 학습 전 후보 구간이다. 모든 이벤트의 실제 상대 시각을 사용했고, 이벤트 사이를 연결하지 않았다. 구간 이동 간격은 1분이다. 원 측정 공백이 설정값을 초과하면 그 위치에서 이벤트를 여러 연속 구간으로 나누고 각 구간 안에서만 후보를 생성했다. 공백 경계를 넘는 보간·외삽은 허용하지 않는다.

3분은 이번 감사를 위한 시험값이며 FloodNet이 보장한 품질 기준이 아니다. 2분·3분·5분 등 가정별 보간 의존도와 결과를 비교해야 한다. 2021년 이전 5분 주기 데이터는 별도 그룹으로 처리할 수 있다.

시간 정의: 30분을 실제 경과시간으로 엄격히 적용하면 t-30, ..., t의 양끝을 포함한 31개 시각이 된다. 여기에 t+15까지 확인하여 총 45분의 범위를 요구했다. 30개의 1분 간격 점만 사용하면 첫 점부터 마지막 점까지는 29분이므로, 구현 시 30개 구간 평균 또는 31개 시각 중 어떤 정의를 쓸지 명시해야 한다.

3분 공백 기준의 223,355개/246,897개는 서로 겹치는 후보이고 독립 표본 수가 아니다. 이상치 검토, 관측 밀도 조건, 학습/검증/시험 분할 및 입력·정답의 구체적인 리샘플링 규칙을 적용하면 최종 수는 더 줄 수 있다.

**상승·하강 분포**

이벤트 전체는 보통 상승 후 하강한다. 따라서 상승 이벤트와 하강 이벤트를 서로 배타적인 두 종류로 나누면 의미가 왜곡된다. 아래 이벤트 집계는 인접 관측값에 양수/음수 변화가 한 번이라도 있는지를 각각 세었으며, 미세한 측정 잡음까지 포함하는 기술통계다.

| 조건 | 이벤트 수 |
|---|---:|
| 상승 구간 포함 | 3,182 |
| 하강 구간 포함 | 3,184 |
| 상승과 하강 모두 포함 | 3,182 |
| 하강만 관측 | 2 |
| 상승만 관측 / 변화 없음 | 0 / 0 |

모델용 분포는 예측 구간을 기준으로 다시 확인했다. 15분 뒤 수위가 현재보다 1cm 초과 높으면 상승, 1cm 초과 낮으면 하강, 그 사이면 정체로 정의했다. 1cm는 이번 감사의 임시 기준이며 실제 센서 잡음과 검증 결과로 조정한다. 이 분류용 수위는 구간 안에서 시간 기준 선형보간한 사후 값이므로, 최종 모델의 입력 생성 방식과는 구분한다.

|---|---:|---:|
| 상승 후보 | 24,677 (11.05%) | 33,301 (13.49%) |

후보가 하나 이상 있는 고수심 이벤트는 요약 최대 수심 기준으로 30분 입력에서 78건, 20분 입력에서 82건이다. 하지만 이들 이벤트의 모든 후보가 임계값 직전 상승 구간인 것은 아니다.

현재 보간 수위는 0.40m 미만이고 향후 15분 안에 0.40m 이상인 실제 배열 측정점이 있는 후보는 30분 입력에서 489개(35개 이벤트), 20분 입력에서 538개(41개 이벤트)다. 메타데이터·배열 불일치 검토 전 수치이며, 동일 이벤트 내 겹치는 후보를 독립적인 위험 사례로 세면 안 된다.

**권장 전처리 순서**

1. 원본 보존, 파일 해시·컬럼명·단위 기록. 센서 ID와 시작 시각으로 이벤트 식별자를 만든다.
2. 천 단위 쉼표를 처리하고 숫자형으로 변환한다. UTC 시작 시각과 초 단위 상대 시각을 결합하고, 수심은 inches × 0.0254로 m 단위로 통일한다.
3. json.loads로 두 배열을 해석하고 배열 길이, 유한값, 시간 순서와 중복을 확인한다. 동일 시간·수위 중복 1개를 제거한다. 서로 다른 수위가 같은 시각에 있을 경우 자동 평균으로 덮지 말고 별도로 표시한다.
4. 요약 필드와 배열의 불일치를 기록한다. 최대 수심·도달시간·지속시간을 학습 정답으로 사용한다면 검토한 시계열에서 정의를 통일하여 계산한다. 미래 최대 수심·전체 지속시간·배수시간·최고점 도달시간을 미래 예측 입력에 넣지 않는다.
5. 긴 공백에서 구간을 나눈다. 짧은 공백 보간에만 제한을 두고, 긴 공백·관측 시작 전·관측 종료 후를 0이나 직선으로 채우지 않는다. 관측 마스크와 마지막 관측 후 경과시간, 보간 비중을 기록한다.
6. 실제 시간 기준으로 1분 간격을 만든다. 예측 시점 이후 측정값으로 과거 입력을 보간하거나 중심 이동평균을 적용하면 미래 정보가 새어 들어간다. 입력 처리에는 예측 시점까지 도착한 측정값만 사용한다. 정답도 긴 공백 안에서 생성하지 않는다.
7. 이벤트를 유지한 채 시간 순서로 학습·검증·시험을 분리하고, 경계를 넘는 이벤트/동일 폭우가 양쪽에 섞이지 않게 관리한다. 이후 각 집합 안에서 구간을 만든다. 동일 센서의 다른 시점 예측과 새 센서 일반화 평가는 별도로 설계한다. 정규화 계수는 학습 집합에서만 계산한다.
8. 30분 입력과 20분 입력 모두 5·10·15분 정답을 만든다. 동일 시험 시점에서 성능을 비교하고, 전체 사용 가능 구간에 대한 적용 범위는 별도로 보고한다. 20분 실험에 더 쉬운/어려운 사례가 추가된 효과를 모델 개선으로 혼동하지 않는다.
9. 센서·이벤트별 표본 수와 상승/하강/정체 비중을 관리한다. 한 센서는 449개 이벤트이고 센서별 중앙값은 3개다. 긴 이벤트·특정 센서·정체 구간이 과도하게 지배하지 않도록 학습 샘플링/가중치를 조절한다. 시험 분포는 임의로 균형화하지 않는다.
10. 현재 수위 유지 예측과 선형 상승속도 예측을 기준 모델로 두고 LSTM을 비교한다. 5·10·15분별 MAE/RMSE 외에 상승 구간 오차, 고수심 과소예측, 임계수심 도달시간 오차와 해당 평가 이벤트 수를 함께 보고한다.

첨부된 이벤트 자료만으로 이벤트 이전 20~30분의 정상 수위를 복구할 수 없다. 이벤트가 시작된 직후에도 예측해야 하는 실제 운용과 연결하려면 센서의 연속 관측 이력 또는 별도 정상 구간이 필요하다. 짧은 입력창이 초기 예측 가능 시점을 앞당기는 효과도 비교한다.
