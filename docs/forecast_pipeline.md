# 외부 수위 예측 파이프라인

이 문서는 현재 저장소에 구현된 데이터 처리와 모델 학습·추론 규칙을 정리한다. 과거 설계 검토의 후보 모델과 실제 학습에 사용한 모델을 구분하며, 현재 배포 기록은 [모델 버전과 최종 평가 조건](a_plan_model_release.md)을 따른다.

## 1. 예측 문제

현재까지 완료된 30개의 1분 구간으로 향후 15개의 1분 구간 수위를 한 번에 예측한다.

| 항목 | 규칙 |
| --- | --- |
| 입력 | 외부 수위 1개 변수, m 단위 |
| 입력 배열 | `(N, 30, 1)`, float32 |
| 정답 배열 | `(N, 15, 1)`, float32 |
| 정답 마스크 | `(N, 15, 1)`, bool |
| 샘플 이동 간격 | 1분 |
| 원본 관측 공백 | 180초 초과 시 연속 구간 분리 |
| 실측 입력 | 최소 27/30 구간 |
| 실측 정답 | 최소 14/15 구간 |
| 입력 보완 | 과거 값 유지, 최대 연속 2개 구간·마지막 실측 후 180초 이하 |
| 정답 보완 | 적용하지 않음 |

구간은 오른쪽 끝을 포함하는 `(T-60초, T]`다. 대표값은 해당 구간의 마지막 유효 관측이다. 예측 원점이 12:30이면 입력은 `(12:00, 12:30]`, 정답은 `(12:30, 12:45]`를 덮는다. 12:30에 측정한 값은 입력에만 속한다.

출력은 미래 각 구간의 마지막 관측 수위에 대한 추정이며, 구간 내 최고 수심이나 실제 대피 잔여시간을 뜻하지 않는다.

## 2. 원본 읽기와 이벤트 검사

`meit_data/io.py`가 `export.csv`에서 다음 컬럼을 읽는다.

- `Sensor ID`
- `Flood Start Datetime (GMT)`
- `Time Series Depth Values (inches)`
- `Time Series Depth Timestamps (seconds)`

수위·상대시각 배열의 길이와 유효성을 검사하고, 시각은 UTC로 변환한다. 수심 변환은 `depth_m = depth_inches × 0.0254`다. 센서 ID와 원 이벤트 시작 시각으로 이벤트를 식별한다.

동일 시각·동일 수위의 중복은 제거한다. 동일 시각의 상충 값과 요약 최고 수심 불일치는 검사 결과에 기록하며, 설정된 보류 이벤트는 학습·평가에서 제외한다. 이벤트 전체 최고 수심·지속시간 등 미래를 포함한 요약값은 모델 입력으로 사용하지 않는다.

원본 검사 근거는 [데이터 감사](../analysis/floodnet_audit_20260910/dataset_audit.md), 설정은 [pipeline_config.json](../configs/pipeline_config.json)에 있다.

## 3. 데이터 분할

겹치는 창을 만들기 전에 이벤트를 나눈다. 동일 이벤트의 구간과 샘플은 모두 하나의 split에 속한다.

- 시작 시각과 UTC 날짜를 기준으로 시간순 train/validation/test_temporal 경계를 정한다.
- 초기 목표 비율은 70/15/15이며, 경계 횡단 이벤트 제외와 24시간 embargo를 적용하므로 실제 비율은 달라진다.
- 학습 시기 안에서 0.30m 아래로부터 도달하는 이벤트가 있는 날짜를 시간순 네 구간으로 나눈다.
- 각 구간에서 seed 42와 SHA-256 순서로 날짜 하나를 고정하고, 그 날짜의 모든 이벤트를 `test_risk`로 옮긴다.
- 모델 오차나 예측 결과로 위험 시험 날짜를 고르지 않는다.

현재 위험 시험 날짜는 UTC 기준 2023-09-29, 2024-10-18, 2025-08-21, 2026-04-19다. 원본에 호우 ID가 없으므로 이벤트 분리가 호우 단위 독립성까지 보장하지는 않는다.

현재 저장된 배열의 샘플 수:

| split | 샘플 수 |
| --- | ---: |
| train | 97,056 |
| validation | 24,857 |
| test_temporal | 20,478 |
| test_risk | 7,962 |

**기존 두 시험 자료는 2026-09-29에 이미 열어본 상태다.** 모델·epoch·입력 특성·경고 임계값 선택에는 사용하지 않으며, 해당 자료의 성능은 탐색 결과로만 취급한다. 객관적인 최종 보고에는 사전에 등록한 새로운 미사용 holdout이 필요하다.

## 4. 1분 구간과 결측 처리

`meit_data/preprocess.py`는 이벤트 내부의 긴 공백에서 연속 구간을 나누고, 관측 범위 안에 완전히 포함되는 1분 구간만 생성한다. 오프라인 구간 원점은 이벤트 시작 시각이다.

각 구간에는 실측 수심, 관측 마스크, 원본 측정 시각, 마지막 관측 이후 경과시간과 입력용 보완값을 보존한다.

입력 결측은 과거의 마지막 실측값으로만 보완한다. 연속 2개 구간 또는 마지막 실측 후 180초를 넘으면 보완하지 않는다. 보완된 칸의 관측 마스크는 false를 유지한다. 예측 원점 이후 관측을 입력 보완에 사용하지 않는다.

정답은 실측값과 원래 마스크를 사용한다. 결측 정답은 NaN으로 남겨 손실과 평가에서 제외하며, 입력용 보완값을 정답으로 복사하지 않는다.

30개 입력과 15개 정답이 한 연속 구간 안에 있고 품질 기준을 만족할 때만 샘플을 저장한다. 서로 다른 이벤트·센서·긴 공백을 이어 붙이지 않는다.

## 5. 정규화와 학습 표본

학습 입력 구간의 실측값을 이벤트·시각 기준으로 중복 제거한 뒤 평균과 표준편차를 구한다.

```text
z = (depth_m - train_mean_m) / train_std_m
```

입력과 관측 정답에 같은 수심 변환을 적용한다. 검증·시험 자료는 저장한 계수로 변환만 한다. 이벤트별 미래 최고 수심으로 정규화하지 않는다.

CV에서는 `meit_model/fold_scaling.py`가 각 fold의 학습 구간만으로 계수를 다시 계산한다. 체크포인트에는 해당 학습에 사용한 scaler를 저장하며 추론 시 한 번만 적용한다.

긴 이벤트가 학습을 지배하지 않도록 이벤트별 총 가중치를 동일하게 하는 학습 sampler를 사용한다. 검증·평가는 원래 표본 분포를 유지한다.

## 6. 기준 모델과 LSTM

기준 모델은 현재 수위를 유지하는 persistence와 최근 5분 실측 수위를 이용한 선형 외삽이다. 비교 시 같은 예측 원점과 정답 마스크를 사용한다.

현재 구현된 `LSTMForecaster`는 외부 수위 1개 변수를 입력받는다.

```text
(B, 30, 1)
→ LSTM(input_size=1, hidden_size=64, num_layers=1)
→ 마지막 은닉상태 (B, 64)
→ Linear(64, 15)
→ (B, 15, 1)
```

미래 정답을 디코더에 넣거나 예측값을 다시 입력하며 15회 반복하지 않는다. `analysis/`에 남아 있는 3변수·residual 구조 검토는 설계 후보이며 현재 구현과 구분한다.

기본 학습은 masked MAE를 사용한다. 위험 인지 학습은 `risk_aware_masked_mae`로 고수심 과소예측에 추가 가중치를 적용한다. NaN에 마스크를 곱하는 방식 대신 유효한 관측 정답 위치를 선택하여 손실을 계산한다.

## 7. 모델 선택과 평가

모델 선택은 train과 validation으로 구성한 개발 데이터에서만 수행한다.

1. 고정된 시간순 CV 4개 fold를 만든다.
2. seed 42·43·44별로 총 12개 fold 모델을 학습한다.
3. window calibration과 5분 선행 경고 event 평가를 함께 검토한다.
4. 미탐, 오경보, precision과 경고 비율을 보고 경고 임계값을 명시적으로 고정한다.
5. 검증 최선 epoch 12개의 중앙값을 반올림한 epoch 수로 전체 개발 데이터를 학습한다.

현재 학습 기록은 개발 창 121,913개, 최종 14 epoch, 외부 예측 경고 임계값 0.30m다. 이 결과는 새 미사용 자료에서의 최종 검증 완료를 뜻하지 않는다.

평가는 예측 시점별 MAE·RMSE, 이벤트별 오차, 상승 구간, 고수심 과소예측, 임계수심 도달 누락·오경보와 경고 선행시간을 함께 본다. 이미 임계값 이상인 경우, 예측에서 미도달한 경우, 계산할 수 없는 경우를 구분한다.

명령과 필수 산출물은 [모델 선택 절차](model_selection_workflow.md)에 있다.

## 8. 추론

`ForecastPredictor`는 체크포인트의 모델 설정·가중치·scaler를 읽고, 품질 검사를 마친 최근 30개 1분 수위를 입력받는다. 정규화 → 모델 추론 → m 단위 복원 → 음수 예측의 0 제한 순서로 처리한다.

결과는 `ForecastResult`로 반환한다. 정상 상태는 `READY`이며, 부적절한 입력은 `INSUFFICIENT_DATA`, 비정상 모델 출력은 `PREDICTION_ERROR`다. 예측 시각은 지정한 원점으로부터 +1~+15분이다.

고빈도 원본 관측을 추론기에 그대로 넣지 않는다. 구간 처리와 품질 검사는 `meit_data/inference_input.py`의 `prepare_input`을 이용하며, 이 함수의 정규화된 X와 추론기가 기대하는 m 단위 수위를 구분하여 이중 정규화를 피한다. 이력이 부족할 때 임의의 0을 붙여 예측하지 않는다.

## 9. 파일과 재현성

`data/processed/`에는 네 split의 NPZ, 관측·구간·샘플 테이블, 설정, scaler와 manifest가 있다. [고정 데이터 계약](../configs/canonical_data_release.json)은 원본 CSV와 각 산출물의 SHA-256을 기록한다. `.gitattributes`는 전처리 자료의 바이트를 보존한다.

학습 가중치와 개별 실험 결과는 Git에서 제외된 `artifacts/`에 보관한다. 소스와 함께 공개하는 학습 요약에는 데이터 fingerprint, 실행 경로와 체크포인트 해시를 기록한다.

```bash
python -m meit_data --verify-only
python -m meit_model.check_data_pipeline
python -m meit_model.final_evaluation_gate
python -m unittest discover -s tests -v
```

새 holdout은 기존 네 split과 이벤트가 겹치지 않아야 한다. 모델 추론 전에 선택 규칙·경로·SHA-256을 고정하고 계약에 `SEALED_UNOPENED`로 등록한다. 기존 시험 자료를 새 holdout으로 이름만 바꾸어 재사용하지 않는다.
