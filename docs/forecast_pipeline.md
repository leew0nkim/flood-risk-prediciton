# MEIT 외부 수위 예측 전체 로직

설계일: 2026-09-12
대상: export.csv 기반 모델 개발과 축소모형 연동
상태: 구현을 위한 설계와 초기 설정. 모델 학습 결과나 실행 가능한 전체 프로그램은 아니다.

**확정된 예측 문제**

현재 시각까지의 30분을 1분 구간 30개로 표현하고, 다음 15분을 1분 구간 15개로 예측한다. 매분 새 관측을 반영하여 15개 예측값을 다시 계산한다.

| 항목 | 설계 |
|---|---|
| 시간 간격 | 60초 |
| 입력 길이 | 30개 구간 |
| 출력 길이 | 15개 구간, 1~15분 전체 |
| 샘플 이동 간격 | 1개 구간 |
| 기본 입력 변수 | 외부 수심 1개, 단위 m |
| 샘플 X / Y | (30, 1) / (15, 1) |
| 배치 X / Y | (B, 30, 1) / (B, 15, 1) |
| 원 측정 간격 허용 | 180초 이하, 초과하면 구간 분리 |
| 입력 실측 구간 | 최소 27/30 |
| 정답 실측 구간 | 최소 14/15 |
| 입력 빈 구간 보완 | 과거 값 유지, 최대 연속 2개 구간 및 마지막 실측 후 180초 이하 |
| 정답 빈 구간 | 보완하지 않고 손실·평가에서 제외 |
| 예측 방식 | LSTM에서 미래 15개 수위를 한 번에 출력 |
| 실행 위치 | Python 모델은 PC, 센서 수집·구동은 Arduino |

90%와 180초는 첫 실험의 설정이며 검증된 센서 품질 기준은 아니다. 앞서 집계한 약 1,524개 이벤트/153,327개 후보는 이상치 검토, 시계열 분할과 아래의 구체적인 구간 규칙 적용 전 참고치다. 최종 개수는 전처리 코드에서 다시 집계한다.

**1. 전체 흐름**

학습:
    CSV 읽기
    → 배열 해석·단위 변환·이벤트 식별
    → 중복 및 불일치 검사
    → 이벤트·날짜 기준 학습/검증/시간순 시험/위험 집중 시험 분리
    → 긴 공백에서 연속 구간 분리
    → 1분 구간 대표값과 관측 마스크 생성
    → 30분 입력 + 15분 정답 샘플 생성
    → 품질 기준 선별
    → 학습 자료로만 정규화 계수 계산
    → 기준 모델 및 LSTM 학습·검증
    → 고정한 두 시험 자료로 시간 일반화와 위험구간 성능 평가
    → 모델·정규화·설정 저장

실시간:
    Arduino 실내·외 수위와 시간 수신
    → 현재 실측 상태 갱신
    → 학습과 동일한 1분 구간 처리
    → 최근 30개 구간의 품질 확인
    → 학습 시 저장한 정규화 적용
    → 향후 15개 구간 예측
    → m 단위 복원
    → 예측 그래프·임계수심 도달 구간 표시
    → 실내 실측값을 별도 위험 계산 모듈에 전달
    → LED·스피커 표시, 장치 제어 모듈에 상태 전달

LSTM이 직접 모터 개방량을 출력하지 않는다. 수위 예측, 위험 해석, 장치 제어는 각각 명시된 입력과 출력을 가진 모듈이다.

**2. 시간을 정확히 정의하기**

완료된 현재 구간의 끝을 T로 둔다. j번째 구간은 (T-60초, T] 형태로 오른쪽 끝을 포함한다. T에 기록된 값은 현재 구간에만 들어가고 다음 구간에는 중복으로 들어가지 않는다.

예측을 12:30에 수행한다면:
- 첫 입력 구간: (12:00, 12:01]
- 마지막 입력 구간: (12:29, 12:30]
- 첫 정답 구간: (12:30, 12:31]
- 마지막 정답 구간: (12:44, 12:45]

따라서 30개 입력 구간과 15개 정답 구간은 정확히 45분을 덮는다. 단순히 시각 30개를 가져오면 양끝 차이는 29분이므로, 그 정의와 혼용하지 않는다.

각 1분 구간의 대표값은 그 구간의 마지막 유효 수위 측정값이다. 값과 함께 실제 측정 시각도 저장한다. 이 선택은 큰 평균화로 급격한 변화를 희석하지 않고, 구간 끝에서 확보한 최신 관측을 쓰기 위한 초기 설계다.

출력은 각 미래 1분 구간의 마지막 관측 수위에 대한 예측이다. 미래의 정확한 00초 순간을 직접 측정한 수위나 그 1분의 최고 수심과 동일한 의미로 표시하지 않는다. 첫 임계값 도달도 분 단위 구간으로 표현한다.

오프라인은 각 이벤트 시작을 구간 원점으로 사용한다. 실시간은 장치 세션의 고정 원점을 사용하고 매번 재설정하지 않는다. FloodNet 이벤트의 원점은 침수 시작으로 선택되므로, 실제 연속 스트림 적용 시 구간 원점 차이가 성능에 미치는 영향도 재생 평가한다.

**3. 원본을 공통 관측 테이블로 변환하기**

필요한 원본 컬럼:
- Sensor ID
- Flood Start Datetime (GMT)
- Time Series Depth Values (inches)
- Time Series Depth Timestamps (seconds)

처리:
1. pandas.read_csv(source, thousands=",")로 숫자의 천 단위 쉼표를 처리한다.
2. json.loads로 수위 배열과 상대 시각 배열을 해석한다.
3. 배열 길이가 같고, 모든 값이 유한하며 상대 시각이 유효한지 검사한다.
4. timestamp_utc = flood_start_utc + relative_seconds.
5. depth_m = depth_inches × 0.0254.
6. event_id = sensor_id와 원 이벤트 시작 시각의 조합으로 고정한다.
7. 이벤트 안에서 시간 순서를 확인한다. 같은 시간·같은 수위는 한 개만 남기고, 같은 시간·다른 수위는 검토 대상으로 분리한다.
8. 각 단계의 제외 사유와 원본 이벤트 식별자를 기록한다.

공통 관측 테이블:

| 컬럼 | 의미 |
|---|---|
| event_id | 원본 이벤트 식별자 |
| sensor_id | 센서 식별자 |
| timestamp_utc | 실제 측정 시각 |
| relative_seconds | 원 이벤트 시작으로부터 경과한 초 |
| depth_m | 외부 수심 |
| source_record | 원본 CSV 레코드 번호 |
| quality_flags | 중복·요약 불일치 등의 검사 결과 |

원본의 최대 수심, 전체 지속시간, 최고점 도달시간, 배수시간은 감사용이다. 미래 정보를 포함하므로 모델 입력으로 넣지 않는다.

알려진 검사 사례:
- CSV 842행: 같은 시각·수위 한 쌍 중복 → 동일 쌍 1개 제거.
- CSV 2997행: 최고점 도달시간 오류와 배수시간 결측 → 요약 필드 오류로 표시. 시계열 자체는 별도 검토 후 사용.
- CSV 2977행: 요약 최고 수심 4.09cm, 배열 최고 수심 40.49cm → 원자료 정합성 확인 전 기본 학습·평가에서 보류.
- CSV 1451행: 실제 배열이 이벤트 시작보다 약 200분 뒤에 시작 → 앞 구간을 인위적으로 만들지 않는다.
- 나머지 수심 요약 불일치도 검토 목록에 넣되, 차이만으로 실제 침수를 이상치로 확정하지 않는다. 고수심 값을 일괄 자르지 않는다.

보류할 이벤트는 행 번호 대신 event_id로 설정에 기록한다. 이후 CSV 행 순서가 바뀌어도 적용 대상을 유지한다.

**4. 학습·검증·시험 분리**

순서는 이벤트 분리 후 구간 생성이다.

- 초기 목표 비율: 과거 70% 학습, 다음 15% 검증, 최근 15% 시간순 시험(`test_temporal`).
- 이벤트 시작 시각으로 정렬하되 날짜 단위 경계로 맞춘다. 실제 경계 날짜와 이벤트·센서 수를 manifest에 저장한다.
- 경계를 가로지르는 원 이벤트는 어느 쪽으로도 쪼개 넣지 않고 해당 경계의 평가에서 제외한다.
- 각 경계 뒤 24시간을 비워 인접 시기의 강한 상관을 완화하는 초기 embargo를 둔다. 실제 비율은 70/15/15와 달라질 수 있다.
- 동일 호우가 여러 센서·여러 날짜에 걸쳐 나타날 수 있다. 호우 ID가 확보되면 같은 호우는 같은 집합에 둔다. 시간 완충만으로 동일 호우를 완전히 분리했다고 주장하지 않는다.
- 동일 이벤트의 모든 연속 구간과 샘플은 같은 집합에 남긴다.
- 시간순 학습 구간 안에서 임계 기준 0.30m를 아래에서부터 도달하는 이벤트가 있는 UTC 날짜를 시간순 4구간으로 나누고, 각 구간에서 seed 42의 SHA-256 순서로 한 날짜씩 모델 학습 전에 고정한다. 해당 날짜의 모든 이벤트를 위험 집중 시험(`test_risk`)으로 이동하며, 같은 날짜의 일부를 학습에 남기지 않는다.
- 위험 집중 시험은 임계 도달 성능을, 시간순 시험은 최신 시기 일반화 성능을 측정한다. 두 시험 자료를 이용해 입력 길이, 결측 기준, 모델 구조, 정규화 계수 또는 학습 중단 시점을 고르지 않는다.

각 집합에서 기간, 센서 수, 상승 구간 수, 0.25m 주의와 0.30m 임계 사례 수를 확인한다. 위험 집중 시험 날짜는 모델 오차를 본 뒤 고르지 않으며, 독립 이벤트 수와 날짜 수를 창 수와 함께 보고한다. 부족한 사례를 무작위 창 단위로 재분배하지 않는다.

**5. 1분 대표값과 관측 마스크 생성**

모든 원본 측정값의 시간 간격을 확인하고, 180초를 넘는 공백에서 연속 구간을 나눈다. 서로 다른 이벤트·센서·연속 구간은 이어 붙이지 않는다.

완전히 관측 범위 안에 들어가는 1분 구간만 생성한다. 전체 이벤트가 45분을 넘더라도, 그 안에 충분한 연속 구간이 없으면 학습 샘플을 만들지 않는다.

구간별 저장값:
- observed_depth_m: 구간 안 마지막 유효 실측값. 실측이 없으면 결측.
- observed: 실측이 있으면 true, 없으면 false.
- source_timestamp: 대표값의 실제 실측 시각.
- last_observation_age_seconds: 구간 끝에서 마지막 실측이 얼마나 오래되었는지.
- causal_input_depth_m: 입력용 값. 실측이 없을 때만 과거의 마지막 값으로 제한적으로 보완.
- segment_id: 긴 공백으로 나눈 연속 구간 식별자.

입력 빈 구간:
- 과거 값 유지(forward fill)를 최대 연속 2개 구간까지 적용한다.
- 마지막 실제 관측 이후 180초를 초과한 값은 쓰지 않는다.
- 직전의 유효 실측이 없으면 채우지 않는다.
- 보완한 값의 observed는 false를 유지한다.
- 입력 구간 끝 T 이후의 측정값으로 입력을 보완하지 않는다.

정답 빈 구간:
- observed_depth_m과 observed를 그대로 사용한다.
- 보완된 입력용 값을 정답으로 복사하지 않는다.
- NaN인 정답은 손실·평가 계산에서 마스크로 제외한다.

이 구조를 사용하면 동일한 저장 시점이 어떤 샘플에서는 입력, 다른 샘플에서는 정답이 되더라도 정답의 실측 여부를 보존할 수 있다.

**6. 30 → 15 샘플 만들기**

각 연속 구간의 1분 테이블에서 현재 인덱스 i를 1개씩 이동한다.

    X_depth = causal_input_depth_m[i-29 : i+1]
    X_observed = observed[i-29 : i+1]
    Y_depth = observed_depth_m[i+1 : i+16]
    Y_mask = observed[i+1 : i+16]

승인 조건:
- X가 30개, Y가 15개.
- X 실측 칸이 27개 이상.
- Y 실측 칸이 14개 이상.
- 입력 보완 후에도 남은 결측·무한대가 없음.
- 입력 30분 + 정답 15분이 하나의 연속 구간에 포함됨.
- 보류된 이벤트가 아님.
- 샘플이 학습/검증/시험 경계를 넘지 않음.

저장:
- X: float32, (N, 30, 1)
- Y: float32, (N, 15, 1), 관측 없는 정답은 NaN
- Y_mask: bool, (N, 15, 1)
- X_observed와 관측 경과시간: 품질 검사·향후 특성 확장용
- event_id, sensor_id, origin_time, split, segment_id: 샘플 메타데이터

30분 입력의 마지막 시각을 origin_time으로 저장한다. 정답은 항상 origin_time 이후의 구간이다.

**7. 정규화와 표본 구성**

첫 모델은 외부 수심만 입력한다. 관측 마스크·경과시간을 추가 특성으로 넣는 실험은 이후 X=(30, 3)으로 명시적으로 변경하여 비교한다.

학습에 사용되는 입력 구간에 속한 실측 수심을 시각·이벤트 기준으로 중복 제거하여 평균과 표준편차를 계산한다. 겹치는 창 때문에 같은 실측값을 수십 번 반복 집계하지 않는다.

    z = (depth_m - train_mean_m) / train_std_m

- X와 관측된 Y에 같은 수심 변환을 적용한다.
- 검증·시간순 시험·위험 집중 시험·실시간은 저장한 평균·표준편차로 transform만 한다.
- 표준편차가 0이거나 유효 학습값이 없으면 학습을 중단하고 원인을 보고한다.
- 이벤트별 최대값으로 나누지 않는다. 미래 최대값이 입력에 영향을 줄 수 있고 0.30m의 절대 의미도 잃게 된다.

긴 이벤트가 학습을 지배하지 않도록 기본 학습 샘플링은 이벤트별 총 가중치를 동일하게 둔다. 각 창의 가중치는 1 / 해당 이벤트의 학습 창 수다. 한 epoch의 추출 창 수는 원 학습 창 수와 같게 두고 반복 추출 가능성을 기록한다. 검증·시험은 원래 분포를 유지한다.

**8. 기준 모델과 LSTM**

기준 모델 A: 현재 수위 유지
    모든 k=1..15에 대해 prediction[k] = 현재 마지막 입력 수위.

기준 모델 B: 최근 수위 변화 선형 외삽
    입력의 최근 5분 안 실측값과 실제 측정 시각으로 기울기를 계산한다.
    실측값이 2개 미만이면 현재 수위 유지로 대체하고 대체 횟수를 기록한다.
    prediction[k] = 마지막 실측 수위 + 기울기 × (예측 구간 끝 - 마지막 실측 시각).
    음수 수심은 0으로 제한한다.

LSTM 기본 구조:
    (B, 30, 1)
    → LSTM(input_size=1, hidden_size=64, num_layers=1, batch_first=True)
    → 마지막 은닉상태 (B, 64)
    → Linear(64, 15)
    → reshape (B, 15, 1)

예측값을 다시 입력으로 넣어 15번 반복하지 않고 15개를 한 번에 출력한다. 디코더에 미래 실제 수위를 넣지 않는다.

초기 학습 설정:
- 손실: 관측된 정답에 대한 masked MAE
- optimizer: Adam
- learning_rate: 0.001
- batch_size: 128
- max_epochs: 50
- early_stopping_patience: 8
- gradient_clip_norm: 1.0
- seed: 42

NaN에 마스크 0을 곱해도 NaN이 남을 수 있으므로, 먼저 관측된 위치만 선택해 손실을 계산한다.

    valid = Y_mask & isfinite(Y)
    if valid.sum() == 0:
        skip_batch()
    else:
        loss = mean(abs(prediction[valid] - Y[valid]))

epoch마다 동일한 역정규화·비음수 후처리를 적용한 m 단위 검증 MAE를 계산하여 최선 모델을 저장한다. early stopping은 검증 자료만 사용한다. 모델 구조와 파라미터는 초기안이며 최적 성능을 보장하는 값이 아니다.

추론과 최종 평가에서는 역정규화 후 음수 수심을 0으로 제한한다. 동일한 후처리를 기준 모델에도 적용하고, 음수 출력이 발생한 비율도 별도로 기록한다. 상한은 임의로 0.30m에 자르지 않는다.

**9. 평가와 모델 선택**

모든 모델은 같은 origin_time과 같은 관측 정답 마스크에서 비교한다.

필수 평가:
- 1~15분 각각의 MAE·RMSE와 실제 정답 개수.
- 전체 15분을 합친 오차.
- 이벤트별 MAE를 먼저 계산한 뒤 평균한 오차.
- 센서별 성능과 이벤트 수.
- 상승·하강·정체 구간별 오차.
- 0.25m 주의와 0.30m 임계 기준 부근 및 그 이상에서의 과소예측 정도.
- 예측 가능한 원점 수 / 전체 평가 원점 수.

상승·하강·정체는 15분 뒤 관측 정답과 현재 대표 수위의 차이가 ±0.01m를 넘는지로 분류한다. 15분 뒤 정답이 없으면 해당 분류 평가에서는 제외하고 개수를 보고한다.

임계수심 도달 평가:
- 현재 이미 임계값 이상이면 '현재 초과'.
- 예측 1~15개 중 첫 임계값 이상 구간을 기록.
- 예측에 교차가 없으면 '향후 15분 예측에서 미도달'.
- 실제 도달 시각 비교는 현재와 도달 전후를 포함하여 미래 15개 구간 모두 실측이 있는 부분집합에서 먼저 평가한다.
- 도달 유무의 누락·오경보와 도달 구간 오차를 함께 보고한다.
- 두 곡선이 모두 교차한 샘플만 보고 성능을 좋게 보이게 하지 않는다.
- 미도달을 도달시간 15분이나 무한히 안전함으로 바꾸지 않는다.

LSTM이 기준 모델보다 개선되는지는 검증 자료에서 판단한다. `test_temporal`과 `test_risk`는 선택된 한 설정의 최종 보고에만 사용한다. 같은 연속 수위 예측에서 0.25m 주의와 0.30m 임계 도달 결과를 각각 계산하며, 데이터가 적으면 독립 이벤트 수와 날짜 수를 함께 표시한다.

**10. 모델 저장물**

구현 시 한 모델 버전에 다음을 함께 저장한다:
- model.pt: 가중치
- scaler.json: 학습 평균·표준편차, 단위
- config.json: 시간 구간·결측·모델·후처리 설정

실시간 프로그램은 가중치만 가져오지 않고 이 묶음을 함께 읽는다. 단위, 입력 길이, 출력 길이, 구간 대표값 규칙이 다르면 시작하지 않는다.

**11. 실시간 예측 루프**

FloodNet에 수신 지연 기록이 없으면 오프라인에서는 측정 시각에 관측값을 사용할 수 있다고 가정한다. 실제 통신 지연이 있는 경우 수신 시각까지 포함해 재생·연동 평가한다.

센서 수집과 예측 주기는 별개다. 센서값은 장치가 지원하는 주기로 계속 받되, LSTM은 1분 구간이 닫힐 때 실행한다. 현재 수위에 대한 관측 경보는 새 실측이 올 때마다 갱신한다.

    on_measurement(message):
        validate_timestamp_units_and_sensor_id(message)
        append_raw_measurement(message)
        update_current_observation_alert(message)

    on_minute_closed(T):
        bins = update_minute_bins_using_only_data_received_by(T)
        history = bins.covering(T - 30min, T]

        if not enough_elapsed_history(history):
            publish_forecast_status("WARMUP")
            invalidate_old_forecast()
            return

        if not history_quality_passes(history):
            publish_forecast_status("INSUFFICIENT_DATA")
            invalidate_old_forecast()
            return

        X = causal_fill_and_transform(history, saved_config, saved_scaler)
        pred = model(X)
        depth_m = nonnegative_inverse_transform(pred, saved_scaler)

        publish_forecast(
            issued_at=T,
            target_bin_ends=[T+1min, ..., T+15min],
            predicted_depth_m=depth_m,
            observed_input_bins=history.observed_count,
            last_measurement_time=history.last_measurement_time,
            model_version=model_version
        )

위 흐름은 구현용 의사코드이며 각 함수를 구현하여 연결해야 한다.

입력이 부족할 때 30개가 될 때까지 0을 붙여 예측하지 않는다. 긴 결측 뒤에는 필요한 이력과 품질이 다시 확보될 때까지 예측을 기다린다. 오래된 예측을 새로운 예측처럼 표시하지 않는다.

연속 운용에서는 수위가 0인 정상 시기에도 이력을 모은다. FloodNet 이벤트 CSV에는 이벤트 전 연속 30분이 없으므로, 그 구간을 0으로 만들어 학습 자료에 추가하지 않는다. 정상 상태에서 시작하는 운용 성능은 연속 데이터나 별도로 수집한 관측으로 검증한다.

**12. 위험 표시와 장치 연결**

FloodNet에는 출입문 치수, 실내 수위, 문 개방력과 대피 완료 여부의 정답이 없다. 모델은 외부 수위 곡선을 예측하고, 다음 모듈에서 설정된 조건의 임계수심 도달 예상 구간을 계산한다. 이 데이터만으로 실제 대피 가능시간을 직접 학습하지 않는다.

표시 상태는 두 축으로 관리한다:
- 관측 상태: 현재 센서값이 유효한가, 현재 기준을 이미 초과했는가.
- 예측 상태: WARMUP / INSUFFICIENT_DATA / READY / EXPIRED.

예측 준비가 되지 않았어도 현재 실측 위험 경보는 동작한다. 예측에 임계값 교차가 없다는 이유만으로 '대피 가능 보장'이라고 표시하지 않는다.

최종 프로젝트 기준은 외부 수위 0.25m 주의와 0.30m 문 개방 위험이다. 외부 수위 교차는 예측 모듈의 위험 지표이며, 실제 문 상태와의 관계는 별도 물리 검증 결과와 함께 해석한다.

실내·외 수위에 대한 물리 모듈:
- 실내 센서값과 외부 예측값을 같은 높이 기준·m 단위로 맞춘다.
- 기획서의 등가수심 계산을 적용하려면 물리적 가정과 문 형상을 확인한다.
- 미래 실내 수위는 현재 센서값만으로 확정할 수 없다. 특히 유입구를 열면 미래 실내 수위가 달라진다.
- '향후 실내 수위 일정' 가정을 쓰는 PoC 계산은 그 가정을 결과에 기록한다.
- 문 개방 한계와 실제 대피 가능성은 축소모형·별도 실험의 검증 대상이다.

장치 제어 상태 흐름:
    관측·예측 기반 주의 표시
    → LED/음성으로 먼저 대피 안내
    → 대피하지 못한 상태를 확인하는 입력
    → 실험으로 정한 문 개방 곤란 조건과 장치 상태 확인
    → 제한적인 유입 요청
    → 현재 실내·외 수위로 반복 확인
    → 실험 종료 조건 또는 중단 입력에서 유입 중지

수위만으로 대피 완료/미완료를 추정하지 않는다. PoC에서는 버튼이나 명시적인 시나리오 입력으로 제공한다. 장치의 최대 실내 수위, 개방량, 최대 작동시간, 종료 조건, 고장 시 동작은 하드웨어 실험으로 확정해야 한다. 모델 출력 배열 자체를 모터 신호로 변환하지 않는다.

초기 설정의 actuation_enabled는 false다. 첫 구현은 예측·표시·작동 요청 로그까지 검증하고, 실험 조건을 구성한 뒤 별도 제어기에 연결한다.

아래 파일명은 구현할 모듈의 제안이다. 이 문서 작성 시 전체 프로그램을 생성하거나 학습하지 않았다.

**14. 구현 시 확인할 핵심 검증**

- 구간 경계의 측정값이 한 구간에만 들어가는가.
- 정확히 45분인 구간에서 30+15 샘플 하나가 생성되는가.
- 27/30 입력과 14/15 정답 기준이 정수 개수로 적용되는가.
- 입력이 동일할 때 origin_time 이후 데이터를 변경해도 입력과 예측이 변하지 않는가.
- 결측 정답 위치를 다른 숫자로 바꿔도 masked loss와 평가값이 변하지 않는가.
- 다른 이벤트나 긴 공백을 넘어 샘플이 이어지지 않는가.
- 정규화에 검증·시험 수심이 포함되지 않는가.
- 오프라인 재생과 실시간 처리기가 같은 과거 자료에서 같은 X를 만드는가.
- 시험 정답의 보완값을 실측으로 세지 않는가.
- 예측 실패·입력 부족 상태에서도 현재 실측 경보가 유지되는가.
- 임계값 미도달, 관측 누락, 이미 초과 상태를 별도로 표현하는가.
