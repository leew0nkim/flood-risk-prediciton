# MEIT 2인 개발 및 축소모형 실험 2주 계획

작성일: 2026-09-12
기간: 착수일 D1부터 D14까지. 실제 시작 날짜는 정해지지 않아 상대 일정으로 작성했다.
대상: AI 개발 담당 2명. 축소모형의 전자팀의 현장 운전 담당자 및 기계 제작 담당자와 협업한다. A/B는 AI 내부 역할이며 특정 개인에게 확정 배정한 이름이 아니다.
최종 실험: 실제 물과 센서·구동장치를 사용하는 축소모형 통합 실험.

**현재 상태와 이번 계획의 범위**

현재 이 대화에서 완료한 것은 FloodNet 데이터 감사, 1분 간격/30분 입력/향후 15개 구간 출력 확정, 전처리·모델·실시간 연동 설계다. 학습 코드와 학습된 모델이 완성된 상태는 아니다.

기존 문서에는 축소모형 데이터 수집, 파인튜닝의 조건, 최종 실험의 책임과 마감이 충분히 명시되지 않았다. 이 계획에서 그 범위를 추가한다.

실험 운영 주관: 개발용 반복 실험과 최종 축소모형 실험은 전자팀이 맡는다. 물 주입·배수·모형 재설정·센서 및 구동부 운전·실측 기록 실행과 전달까지 전자팀이 총괄한다. AI팀은 필요한 데이터 조건, PC 수집 프로그램·모델 연동, 파인튜닝과 예측 평가를 맡는다. 기계팀은 구조 제작·수정과 문 개방 조건 확인을 지원한다. 실험 시나리오는 AI팀이 데이터 요구사항을 제시하고 전자팀과 구현 가능성을 함께 확인한다. 실제 전자팀 현장 담당자와 준비 일정은 D1에 구체화한다.

전체 순서:
    데이터 전처리 + 모델 구조 구현
    → FloodNet 학습·검증 및 기본 모델 평가
    → 축소모형 센서 보정·통신 연결
    → 축소모형의 독립적인 실험 데이터 수집
    → 기존 모델 적용 결과 확인
    → 축소모형 학습 자료로 파인튜닝
    → 별도 검증 실험으로 모델 선택
    → 모델·전처리·제어 조건 고정
    → 학습에 쓰지 않은 새 축소모형 실험
    → 결과 분석·시연·인계

모델 구조를 먼저 구현하고 데이터를 학습시켜 학습된 모델을 얻는다. 따라서 '데이터 학습'과 '모델 제작'을 서로 독립적인 순차 작업으로 보지 않는다. 데이터 준비와 모델 코드 작성은 동시에 진행한다.

축소모형의 실시간 동작 흐름:
    실내·외 수위 센서 → Arduino → PC 수신·기록
    → 실외 수위 30분 입력으로 향후 1~15분 수위 예측
    → 현재 실내 수위와 예상 실외 수위를 이용한 위험 판단
    → LED·스피커 대피 안내
    → 대피 미완료 입력과 사전에 정한 모형 제어 조건 확인
    → 유입구 개방 요청·실제 개방
    → 실내·외 수위 재측정 → 종료 조건 확인 → 유입구 폐쇄

실내 수위 예측이나 대피 여부 판단은 FloodNet 수위 예측 모델의 학습 목표가 아니다. 대피 미완료는 버튼 등 별도의 입력으로 확인한다. 예측 입력 30분이 모이기 전에도 현재 실측에 따른 안내는 동작하도록 구성한다. 예측 수위의 임계값 도달 시간은 정해진 가정에 따른 추정이며, 실제 안전한 대피 시간을 보장하는 값으로 표시하지 않는다.

센서 보정은 거리·수위의 영점, 단위, 높이 기준을 맞추는 과정이다. 파인튜닝은 기존 모델의 가중치를 축소모형 데이터로 추가 학습하는 과정이다. 장치의 개방·종료 조건을 조정하는 것은 제어 설정이다. 세 작업의 변경 이력을 구분한다.

**일정의 전제**

- AI 두 사람은 일반 개발일에 각 3~4시간을 확보한다는 가정이다. AI팀은 초기 연동 점검과 필요한 소프트웨어 문제 해결을 지원한다. 개발용·최종 실험은 전자팀이 현장 운전하고, 기록 자동화가 검증되면 AI 담당은 전달받은 파일의 품질 확인과 모델 작업을 병행한다. 전자팀의 현장 운전 가능 시간도 별도로 확보해야 한다.
- D3까지 실내·외 센서값을 기록할 수 있는 구성, D6까지 반복 수위 실험이 가능한 수조·센서 구성을 확보한다.
- D8까지 LED·스피커·유입구의 작동과 중단 입력을 확인할 수 있다는 가정이다.
- 실제 장치 준비일은 아직 확인되지 않았다. 준비가 늦어지면 아래의 데이터 수집·파인튜닝·새 실험 일정도 늦어진다.
- 설정은 60초 간격, 30개 입력 구간, 15개 출력 구간으로 유지한다.
- 30+15 구간 한 샘플에는 실제 45분의 기록이 필요하다. 반복 실험은 회당 60분을 우선 계획하고, 기록 품질에 따라 60~90분으로 늘릴 수 있다.
- 짧은 시연 영상을 빠르게 재생하는 것은 가능하지만, 1초 기록을 1분 기록이라고 바꾸어 실측 학습 자료로 사용하지 않는다.

**두 사람의 지속 책임**

| 영역 | A: 데이터·축소모형 연동 책임 | B: 모델·판단·실험 평가 책임 |
|---|---|---|
| 공개 데이터 | 읽기·품질 검사·1분 처리·이벤트 분할·샘플 생성 | 정규화·학습 로더·기준 모델·LSTM |
| 모델 전달 규약 | X/Y/Y_mask와 이벤트·시각·분할 정보 전달 | 예측 함수·모델 파일·정규화 계수 전달 |
| 축소모형 준비 | 전자팀이 보정한 센서의 PC 수신·단위·시각 동기화 점검 | 모델 입력 적합성, 위험 상태와 출력 형식 점검 |
| 축소모형 데이터 수집 | PC 기록 프로그램·실험 ID 규칙 인계, 전자팀이 전달한 원자료·구동 로그 품질 관리 | 필요한 수위 패턴·길이·용도 분할 설계, 전자팀과 시나리오 협의 |
| 파인튜닝 | 축소모형 학습/검증 자료 전처리와 버전 관리 | 파인튜닝 실행·원 모델 비교·채택 여부 판단 |
| 실시간 동작 | 30분 버퍼·센서 수신·LED/스피커/장치 명령 전달 | 매분 15개 예측·위험 계산·개방/종료 요청 로직 |
| 최종 실험 | 전자팀의 PC 수신·장치 통신 문제 지원, 전달받은 명령·실측 로그 확인 | 모델 버전 고정, 예측 상태 점검 지원, 평가·결과 해석 책임 |
| 중단 | 통신·기록 이상 시 중단 요청, 소프트웨어 명령 중지와 로그 보존 | 판단·예측 이상 시 중단 요청과 원인 기록 |
| 최종 산출물 | 데이터·전처리·연동 코드와 운영 방법 | 모델·성능표·파인튜닝 비교·최종 결과 보고 |

전자팀은 센서 설치·보정, 수조·펌프·유입구 운전, 물 주입·배수·재설정, 현장 중단 조작과 기록 파일 전달을 맡는다. 기계팀은 구조 제작·수정과 문 개방 조건·기구 한계 확인을 지원한다. AI팀은 초기 연동과 필요한 통신·예측 점검을 지원하고 학습·평가를 진행한다. AI 담당자가 수위 예측 결과만으로 하드웨어의 허용 개방량이나 최대 실내 수위를 임의로 정하지 않는다.

| D14 | 전자팀의 현장 시연에 맞춰 PC 연동·기록 프로그램 지원. 데이터·전처리·연동 코드 인계 | 모델·실험 결과 설명, 발표 자료와 모델 버전 인계 | 센서 → 예측 → 안내 → 개방 → 재측정 → 폐쇄 시연 및 최종 보고 |

D6~D8 개발용 실험은 모델 학습 자료 수집을 위한 별도 운전 모드와 제어 정책을 기록한다. D11~D12 최종 통합 실험의 운전 모드와 차이가 있으면 평가에 명시한다. 유입구 동작이 외부 수위를 바꾸는 경우 같은 입력 이력에 대한 미래가 제어에 의존할 수 있으므로, 밸브·펌프 상태를 반드시 로그에 남기고 그 제한을 분석한다.

D13에 최종 시험 결과를 보고 모델을 다시 학습하거나 위험 기준을 바꾸면 기존 최종 시험은 개발 자료가 된다. 변경된 버전은 새 독립 실험으로 다시 평가해야 하며, 새 실험 시간이 없으면 그 버전의 최종 성능이 검증되었다고 표시하지 않는다.

**축소모형 실험 데이터의 구성**

계획 수량은 일정 산정을 위한 탐색적 목표다. 이 수량이 충분한 학습 성능이나 통계적 신뢰도를 보장하지 않는다.

| 조건 | 파인튜닝 학습용 | 모델 선택 검증용 | 최종 평가용 새 실험 | 합계 |
|---|---:|---:|---:|---:|
| 완만한 수위 상승 | 3회 | 1회 | 2회 | 6회 |
| 빠른 수위 상승 | 3회 | 1회 | 2회 | 6회 |
| 상승 후 정체·하강 | 3회 | 1회 | 2회 | 6회 |
| 합계 | 9회 | 3회 | 6회 | 18회 |

- 수량은 모델용 수위 기록 실험 기준이다. 통신 오류·중단 입력의 짧은 개발용 점검은 별도로 한다.
- 회당 60분이면 모형 운전·관측만 총 18시간이다. 이는 AI 담당 개인에게 배정하는 18시간의 물리 실험 노동이 아니라 팀 전체의 실험 설비 사용 시간이다. D6~D8은 하루 4회로 4시간, D11~D12는 하루 3회로 3시간의 순수 관측이 필요하며 전자팀의 준비·배수·재설정 시간을 추가한다. 기록 자동화 여부와 별개로 현장 운전 담당자를 배정한다.
- 각 실험은 모형을 재설정하고 새로 수행한다. 같은 기록을 잘라 여러 독립 실험으로 세지 않는다.
- 학습/검증 용도는 기록을 보기 전에 run_id로 정한다. 최종 6회는 D10 모델 고정 후 새로 수집한다.
- 같은 실험의 겹치는 창은 반드시 같은 집합에 둔다.
- 동일 조건 안에서도 유입 속도·시작 수위 등의 반복 조건을 기록한다. 완전히 같은 시퀀스를 복사한 반복을 독립 근거로 삼지 않는다.
- 60분 기록은 이상적인 경우 45분 창을 1분씩 이동해 최대 16개 생성한다. 학습 9회면 최대 약 144개 창이며 실제로는 결측·품질 기준 때문에 더 줄 수 있다. 독립 실험 단위는 9회다.
- 입력 30분 이력에는 실제 수위 변화가 포함되도록 시나리오를 설계한다. 미래에 임의로 바꾸는 펌프 조작은 현재 수위만으로 예측할 수 없는 외부 요인이 될 수 있으므로 제어 시각을 기록한다.
- 1분 대표값과 27/30 입력·14/15 정답 기준은 FloodNet 단계와 동일하게 적용한다.
- 축소모형 데이터에서도 실제 측정값은 m 단위로 유지한다. 임의로 시간이나 수위를 늘려 원본 도시 침수 기록인 것처럼 취급하지 않는다.

**파인튜닝 단계의 구체적인 역할과 판단**

A의 책임:
1. 전자팀이 확인한 실내·외 센서 영점·높이 기준·보정값을 받아 PC에서 단위·값이 일치하는지 확인하고 버전을 저장한다.
2. run_id별 원자료, 시나리오, 실제 시간, 구동 상태를 저장한다.
3. 모형 학습 9회/검증 3회의 자료를 동일한 전처리로 변환해 B에게 전달한다.
4. 최종 시험 6회는 모델 고정 전 튜닝에 제공하지 않는다.
5. 센서 위치나 수조 구조가 바뀌면 해당 실험과 보정 버전을 구분한다.

B의 책임:
1. 기존 FloodNet 모델 M0와 정규화 계수를 복사·보존한다.
2. M0가 모형 검증 자료에서 내는 오차를 먼저 계산한다.
3. 초기 시도는 LSTM 본체를 고정하고 마지막 15개 출력층만 추가 학습한다. 데이터가 적을 때 전체 가중치를 바꾸는 범위를 줄이기 위한 제안이다.
4. 첫 파인튜닝 설정은 학습률 0.0001, 최대 10 epoch, 검증 개선 중단 3 epoch, batch size 16으로 둔다. 학습 자료가 더 적으면 실제 배치 수와 독립 실험 수를 함께 기록한다.
5. 기본 모델의 정규화 계수를 우선 유지한다. 모형의 검증·최종 시험 데이터로 정규화 계수를 다시 맞추지 않는다.
6. M0와 M1은 같은 검증 run_id, origin_time, 정답 마스크에서 비교한다. 입력·정답은 각각 30/15를 유지한다.
7. 전체 평균뿐 아니라 각 실험 조건과 상승·임계수심 부근 성능을 본다.
8. 검증에서 개선된 모델을 D10에 선택한다. 개선되지 않으면 파인튜닝을 시도했다는 결과를 남기고 M0 또는 검증에서 선택된 기준 모델을 사용한다.
9. 원본 도시 침수에 대한 성능 유지 확인은 미리 남겨 둔 원본 검증 자료에서 비교한다. 원본 최종 시험에 맞춰 추가 조정하지 않는다.

파인튜닝을 계획에 포함한다는 것은 수행하고 효과를 검증한다는 뜻이다. 반드시 성능이 좋아진다는 뜻은 아니다. 축소모형에서 조정된 모델의 성능으로 실제 반지하에서의 성능을 입증했다고 주장하지 않는다.

**최종 실험의 책임**

| 작업 | 주책임 | 확인·보조 |
|---|---|---|
| 모델 평가 목적·필요 수위 패턴·기록 길이·분할 작성 | B | A, 전자팀이 구현 가능성 확인 |
| 실제 펌프·밸브 운전 절차와 물리 실험 시나리오 작성 | 전자 담당 | A/B가 데이터·평가 요구사항 확인 |
| 센서 설치·물리 보정·배선 점검 | 전자 담당 | A가 PC 수신값 확인 |
| PC 통신·시각·원자료 저장 점검 | A | B |
| 유입구·구동부·중단 방법 및 실험 준비 확인 | 전자팀 | 기계팀이 문 조건·구조 한계 확인, A/B가 소프트웨어 준비 확인 |
| 물 주입·배수·모형 재설정·실험 현장 운전 | 전자 담당 | A/B가 데이터·예측 모니터링 |
| 모델 버전·예측·위험 상태 모니터링 | B | A |
| 실험 중 이상 발견 시 중단 | 누구나 요청, 지정된 전자 현장 담당자가 장치 중단 조작 | A/B가 PC 명령 중지·로그 보존 |
| 기록 프로그램 실행·원자료·명령·장치 응답 로그 저장 및 전달 | 전자팀 | A가 프로그램·파일 형식 지원 |
| 전달받은 로그의 누락 확인·버전 보존·학습 자료 처리 | A | B |
| 예측 오차·경보·임계 도달 평가 | B | A가 시각·결측 검토 |
| 수위차·유입 종료·문 개방 실측 및 물리 결과 정리 | 전자팀 | 기계팀이 문 개방·구조 관련 확인 지원, A/B가 로그와 예측 분석 |
| 전체 결과 보고와 한계 설명 | B | A |
| 최종 시연 현장 운전 | 전자 담당 | A가 PC 연동, B가 모델 결과 설명 |

개발용 반복 실험과 최종 실험에 같은 역할 경계를 적용한다. AI팀이 책임지는 실험 결과는 데이터 품질·모델 연동·예측 성능이다. 물리 장치 운전과 실험 기록 실행은 전자팀이 주관하고, 기구 성능 확인은 기계팀이 지원한다. 통합 결과는 함께 검토한다. 계획서의 '실험 책임'은 팀 내 실행 책임을 뜻한다. 실제 실험 장소의 운영 규정과 장치 제작 담당자의 확인 절차에 맞춰 진행한다.

**최종 실험에서 남길 기록**

예측:
- 각 예측 기준 시각, 1~15분의 수위 예측, 실제 정답, 관측 마스크, 모델 버전.
- 시점별 MAE/RMSE, 실험별 오차, 상승 구간 과소예측.
- 예측을 만들 수 있었던 횟수와 자료 부족으로 만들지 못한 횟수.
- 현재 임계값 초과, 예측에서 처음 도달한 구간, 예측 기간 내 미도달을 구분.
- 실제 도달 여부·도달 구간과 예측의 차이.

연동:
- 센서 측정 시각, PC 수신 시각, 예측 생성 시각.
- LED·음성 안내 요청 시각과 실제 동작 확인.
- 대피 미완료 버튼 또는 시나리오 입력.
- 유입구 개방 요청·응답·실제 개방 시각.
- 개방 전후의 실내 수위, 실외 수위, 수위차.
- 종료 요청·응답·실제 폐쇄와 종료 이유.
- 장치 상태 이상 및 중단·재시도.

문 개방:
- 같은 실험 조건에서 개방 전후 문 개방 여부와 실내·외 수위.
- 가능하면 기계 담당자가 개방력을 측정하고 단위와 측정 방법을 기록한다.
- 개방력을 측정하지 않았다면 문 개방력 감소를 수치로 입증했다고 쓰지 않는다.

동일한 센서 스트림에 M0·M1·기준 모델을 함께 적용하면 예측 오차를 같은 조건에서 비교할 수 있다. 실제 유입구는 D10에 정한 한 제어 정책으로 운전한다. 다른 모델을 선택했을 때 장치의 물리적 결과까지 같았을 것이라고 추정하지 않는다.

최종 외부 수위 기준은 0.25m 주의와 0.30m 문 개방 위험으로 고정한다. 문 형상·실내 수위 조건에 따른 실제 개방 및 종료 조건은 별도 물리 검증 결과와 함께 관리하며, 수위 측정만으로 대피 완료 여부를 판단하지 않는다.

**중간 완료 기준과 지연 대응**

D3:
- A가 학습 샘플을 생성하고 센서 로그를 받을 수 있다.
- B의 모델이 30개 입력에 15개 출력을 반환한다.
- 센서 기록이 아직 불가능하면 같은 날 제작 일정과 수집 시간을 다시 배정한다.

D5:
- M0와 원본 성능표가 있다.
- 입력 처리부터 예측 출력까지 재생으로 연결된다.
- 물 없이 명령 전달·응답을 확인한다.

D8:
- 개발용 실험 12회와 전처리 결과가 있다.
- 개방·유입·재측정·폐쇄 흐름을 모형에서 확인했다.
- 기록이 부족하면 추가 수집 시간을 배정하고, 파인튜닝 채택 여부는 보류한다. 부족한 실험을 복제하여 수량을 맞추지 않는다.

D10:
- 최종 모델·보정값·전처리·위험 판단·장치 설정을 고정한다.
- 최종 실험 조건과 보고 항목을 정해 둔다.

D12:
- 고정 이후의 최종 실험 6회와 결과 로그가 있다.
- 실패한 실험도 숨기지 않고 원인·재시험 여부를 기록한다.

D6까지 반복 수위 기록을 시작하지 못하면 2주 안에 계획한 파인튜닝과 새 최종 실험을 모두 마치기 어렵다. 코드·공개 데이터 모델·재생 검증은 계속 진행하되, 실제 축소모형 수집 및 최종 실험에 필요한 날짜는 뒤로 이동한다. 재생 시연을 실제 실측 기반 파인튜닝·실험 완료로 대체해 보고하지 않는다.

**매일 인계할 내용**

하루 마지막 15분에 다음만 공유한다:
1. 오늘 생성·변경한 데이터와 모델·설정 버전.
2. 통과한 단계와 재현 방법.
3. 실패 원인·제외된 실험·불확실한 값.
4. 다음날 상대방에게 필요한 파일이나 장치 상태.

AI → 전자팀: 필요한 수위 변화·회당 기록 시간·실험별 용도, 수집 프로그램과 실행 방법, 센서/PC 통신 규격.
전자팀 → AI A: 실험 ID, 실제 측정 시각, 실내·외 수위(m), 펌프·밸브 상태, 실험 조건·보정 정보가 포함된 원자료와 오류·중단 기록. A는 첫 기록을 확인한 뒤 반복 수집용 형식을 확정한다.
A → B: 원자료/1분 관측 테이블, X/Y/Y_mask, 실험 ID·센서 ID·시각, 학습/검증 구분, 보정·결측 정보.
B → A: 모델 및 정규화, predict 함수, 출력 15개 시각·단위, 예측 상태, 임계 도달 구간, 작동 요청 형식.

**D14 인계 묶음**

- 원본·전처리·실험 자료와 run_id별 용도·조건 목록.
- M0, 파인튜닝 후보 M1, 최종 선택 모델과 정규화·설정.
- 공개 데이터 평가와 축소모형 파인튜닝 전후 비교.
- 최종 새 실험 6회의 예측·연동·문 개방 관측 결과.
- 센서 수신·전처리·예측·표시·장치 통신 코드 및 실행 순서.
- 시연 영상과 실패·제한 사항.

**기술 참고**

가중치 일부를 고정하고 선택한 층을 학습하는 구현 방식은 [PyTorch 전이학습 튜토리얼](https://docs.pytorch.org/tutorials/beginner/transfer_learning_tutorial.html)을 참고한다. 해당 자료는 컴퓨터 비전 예시이며, 이 계획의 출력층 중심 LSTM 조정은 작은 축소모형 데이터에 적용해 검증할 초기 제안이다.

학습·검증·최종 시험을 분리하고 정규화·모델 선택에 시험 자료를 사용하지 않는 원칙은 [scikit-learn 데이터 누수 가이드](https://scikit-learn.org/stable/common_pitfalls.html)를 따른다.

기본 입출력·전처리·실시간 처리 규약은 [전체 로직 설계서](forecast_pipeline.md)를 따른다. 이 문서는 그 설계에 축소모형 파인튜닝과 최종 실험 책임·일정을 추가한다.
